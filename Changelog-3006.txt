Asuswrt-Merlin 3006.xxx Changelog
=================================

3006.102.8_beta3-dav20 (04-Jul-2026)
 - NEW: ctrld is now built from source in CI (pinned v1.5.3) with a local
         speed patch (release/src/router/ctrld/patches/) instead of shipping
         the stock release binary. In --cd mode ctrld regenerates its config
         from the Control D API on every start and discards any local TOML,
         so performance knobs are injected via environment variables that the
         patched binary understands (a stock binary ignores them safely).
 - NEW: DNS speed tuning, all baked in and on by default on the slim build:
         serve-stale cache (answer from expired cache while the upstream is
         slow/unreachable; nvram ctrld_serve_stale, default 1), optional cache
         TTL override (ctrld_ttl, default 0 = respect real TTLs), and LAN
         discovery (mDNS/ARP/DHCP/PTR probing) disabled (ctrld_discovery,
         default 0) - dnsmasq fronts all LAN queries so ctrld only ever sees
         127.0.0.1, making discovery pure overhead.
 - CHANGED: DoH3 (HTTP/3 / QUIC) upstream is now the DEFAULT (ctrld_doh3=1):
         faster reconnects, no head-of-line blocking.
 - CHANGED: webui (WAN page, Control D section): added "Serve stale cache"
         and "Cache TTL override" controls; DoH3 description updated.

3006.102.8_beta3-dav19 (04-Jul-2026)
 - REBASE: version label moved alpha2 -> beta3 to match Merlin 3006.102.8 beta3.
 - BACKPORT (Merlin 3006.102.8 beta2 -> beta3, software only, no driver/blob
         merges): rc: dhcpc-event script moved to end of event; httpd: correct
         IPv6 prefix length for LAN/router IP; rc: don't assign the whole /56 to
         br0 (limit to /64); rc+webui: rework user-defined IPv6 WAN prefix;
         webui: Wireless Log popup UI4-aware, add missing state.js dep,
         incremental client-list DOM diff, traffic analyzer no longer tied to
         bwdpi, remove obsolete USB modem tweak.
 - CHANGED: the DNS-independent clock failsafe now runs on ALL GT-BE98 builds
         (default / rog / slim), not just the Control D slim. It moved into the
         watchdog: while the clock is unset (ntp_ready != 1) and the WAN is
         reachable, it force-syncs against IP-literal NTP servers (no DNS) about
         every 2 min, backgrounded so the watchdog never blocks, and stops as
         soon as the clock is set. The stock ntp daemon only knows its pool by
         HOSTNAME (pool.ntp.org), so a dead/misconfigured upstream DNS otherwise
         left the clock stuck at the ~2024 boot epoch forever. (start_ctrld
         keeps its own immediate sync for ctrld's TLS on the slim build.)
 - FIXED: removed a duplicated "restart ntpd every 24h" watchdog block - the
         gnuton base already had it, and the dav15 Merlin backport (#43c4b107b9)
         added a second copy, so ntpd was being restarted ~every 12h.

3006.102.8_alpha2-dav18 (30-Jun-2026)
 - CHANGED: ctrld clock handling is now keyed on NETWORK availability instead
         of guessing the clock by a magic epoch (the box boots at 2024-01-01,
         so the old "valid if > 2020" / "> 2026" thresholds misfired). If NTP
         hasn't set the clock, start_ctrld() forces a one-shot sync against
         IP-literal servers; busybox `ntpd -q` exits 0 only if it actually
         reached a server, so its exit code is the network probe: success ->
         clock fixed -> launch; failure (no link) -> defer and let the watchdog
         retry. The 30s ntp_ready poll is gone, so a restart with a working
         (or manually set) clock comes up at once.
 - ADDED: ctrld_check (3-min watchdog) self-heals a "ctrld up but dnsmasq not
         pointed at it" state - if ctrld is serving on :5354 but dnsmasq lacks
         server=127.0.0.1#5354, it repoints dnsmasq (covers ctrld binding after
         start_ctrld's verification window). Fires only on a real mismatch.

3006.102.8_alpha2-dav17 (30-Jun-2026)
 - FIXED: regression from dav16 - ctrld ran but dnsmasq was NOT pointed at it
         (no server=127.0.0.1#5354), so DNS resolved via the normal upstream
         and bypassed Control D (device stopped showing in the CD dashboard).
         Cause: the ":5354 bound?" check only looked at IPv4 /proc/net/udp,
         but ctrld binds an IPv6 wildcard (:::5354) which lives in
         /proc/net/udp6 - so the check failed and start_ctrld() skipped the
         dnsmasq repoint. Now checks both /proc/net/udp and /proc/net/udp6.

3006.102.8_alpha2-dav16 (30-Jun-2026)
 - FIXED: GT-BE98 Control D restart is now reliable. start_ctrld() (a)
         treats an already-valid system clock as ready, so a manual `date`
         fix starts ctrld immediately instead of always waiting the full
         30s; (b) waits for the OLD ctrld to fully exit before relaunching
         (its CD config pins an explicit :5354 listener with no port
         fallback, so a lingering socket made the new instance Fatal on
         bind and die); (c) repoints dnsmasq at ctrld ONLY after confirming
         ctrld actually bound :5354 (polls /proc/net/udp), otherwise leaves
         dnsmasq on the normal resolver and lets the 3-min watchdog retry -
         closing the "process alive but not listening" hole that black-holed
         DNS. Note: ctrld's own restart/reload/stop only work for an
         installed service, not our `ctrld run --cd --daemon`, so kill+
         relaunch is the only option.
 - ADDED: clock failsafe in start_ctrld() - if NTP hasn't set the time
         (e.g. the configured upstream DNS is dead, which stalls NTP), force
         a one-shot sync against IP-literal NTP servers (Cloudflare/Google
         anycast, no DNS needed) so ctrld's TLS can validate. The launch is
         NOT gated on it: ctrld may be the only working resolver when the
         upstream DNS is dead, and (c) above keeps a bad clock from breaking
         DNS.
 - CHANGED: baked ctrld updated 1.5.2 -> 1.5.3 (committed arm64 blob).
 - NEW: "Restart Control D" button on the WAN page (pure restart, saves no
         settings) + a ctrld-restart SSH helper (/usr/sbin/ctrld-restart);
         both run "rc_service restart_ctrld".
 - BACKPORT (Merlin 3006.102.8, security/packages only, no driver/blob/GPL
         merges): dnsmasq fix double-free in blockdata_expand(); OpenSSL
         1.1.1 CVE fixes #891 (5 more from Ubuntu ESM); rc: restart ntpd
         every 24h. (Most other .8 security fixes - OpenSSL #885, UPnP
         rule fix, busybox xxd, CA bundle - were already in this base.)

3006.102.8_alpha2-dav1 (xx-Jun-2026)
 - RELEASE: GT-BE98 now builds THREE images from one branch via the CI
         matrix: two "original" full-featured builds (default, rog, NO
         Control D, no slim prune) and one "slim" build (default theme +
         baked Control D + the space-saving prune). All shared changes
         (Spatial Reuse, Wi-Fi unlock, EU channels, 6 GHz channel-list
         fix, etc.) land in all three; only the slim build gets ctrld +
         the prune (gated CTRLD=y). The slim build downloads the LATEST
         official ctrld arm64 release at build time (via the GitHub
         releases/latest redirect, no API), falling back to the committed
         blob. Version suffix: default = alpha2-dav14, rog = ..._rog,
         slim = ...-ctrld.
  - NEW: GT-BE98 built-in Control D (ctrld) DNS forwarder (WAN >
         Control D).  The arm64 ctrld binary (v1.5.2, MIT) is baked
         into the read-only rootfs - never /jffs - and survives factory
         reset and firmware upgrades.  Enter your resolver ID, tick
         Enable, Apply: ctrld runs as a local forwarder on 127.0.0.1:5354
         (no --iface, so it never touches dnsmasq/jffs itself) and the
         firmware points dnsmasq at it, disables native DoT and bypasses
         WAN DNS while active.  Off by default; starts LAST at boot,
         backgrounded and gated, so it can never block boot/brick the
         router, with a 3-minute respawn watchdog.  Update by re-baking
         a newer binary and rebuilding.
  - CHANGED: Control D now runs in native --cd mode (ctrld run --cd
         <ResolverID>) so it registers as a DEVICE in the Control D
         dashboard / status page and pulls the full admin-panel profile,
         not just the raw DoH endpoint. --proto selects DoH vs DoH3
         (HTTP/3 / QUIC) - the web-UI HTTP/3 toggle now works; the device
         name comes from --custom-hostname (lan_hostname). ctrld's CD-mode
         listener auto-falls-back to 5354 (53 held by dnsmasq), which is
         the port dnsmasq forwards to. Cache size stays configurable
         (--cache_size); serve-stale / TTL-override are not exposed by
         --cd (ctrld respects real record TTLs) and were removed from the
         web UI. No --listen (forces no-config mode) and no --iface (so
         dnsmasq/jffs are untouched).
  - PREV: Control D ran from a firmware-generated ctrld.toml
         (tmpfs) instead of cloud --cd mode.  It forwards to the
         resolver's own DoH endpoint (your admin-panel policy still
         applies server-side) on a FIXED 127.0.0.1:5354, with the
         Control D anycast pinned as bootstrap_ip so it needs no DNS
         to start - fixing a start-up race where ctrld could not fetch
         its cloud config and exited.  Start now also waits (bounded)
         for ntp_ready, and ctrld output is logged to /tmp/ctrld.log
         instead of being discarded.  New web-UI options (WAN > Control
         D): DNS cache on/off, cache size (default 65536), serve-stale,
         TTL override, HTTP/3 (DoH3), and verbose logging.
  - FIXED: GT-BE98 wireless channel-list generation (backport of Gnuton
         PR #973): fall back to the regular chanspec hook when the AiMesh
         DWB-derived chanspec list is empty, and guard missing 20 MHz
         channel buckets - so the 6 GHz Wireless General page renders its
         channel list after selecting 320 MHz.
  - FIXED: ctrld boot start is now fully non-blocking - deferred to a
         detached background shell (rc ctrld_check) ~20s after boot,
         so its bounded ntp/pids waits and dnsmasq regen can never
         stall start_services / delay boot.
  - CHANGED: ctrld tmpfs logs (/tmp/ctrld.log, /tmp/ctrld_run.log) are
         now capped (trimmed to last 64 KB past 128 KB, every 3 min via
         the ctrld_check cron) so they can never eat RAM.
  - SLIM: GT-BE98 image trimmed so it fits the device's space-tight
         dual-image flash (the ROG image + baked ctrld no longer fit the
         inactive partition for a normal web-UI update). Disabled for
         GT-BE98: AiCloud 2.0 + Cloud Sync (WEBDAV/SMARTSYNCBASE) and Tor;
         dropped all language dictionaries except EN/RU/UK; and the Samba
         (SMB) file-sharing server + Ookla speedtest binaries are removed
         from the final image. AiProtection, OpenVPN, media server, etc.
         all stay. Frees ~8 MiB so the build flashes/updates normally.
         (BWDPI stays enabled: AMAS code references it unconditionally,
         so BWDPI=n breaks linking.)
  - NEW: GT-BE98 per-band "Spatial Reuse (OBSS-PD)" slider on the
         Wireless > Professional page.  Raises the carrier-detect
         threshold so the radio transmits over weak neighbouring
         Wi-Fi (better airtime in a congested area).  Applies live
         via "wl sr_config" without restarting wireless / dropping
         clients, and shows the channel utilisation before/after.
         Off restores the default behaviour.
  - NEW: "Auto-detect" checkbox for Spatial Reuse (ON by default) -
         the router scans the air (chanim OBSS) every 15 minutes via a
         cron job and picks the level automatically per band, with a
         2-level deadband and a safety cap; the slider is disabled and
         shows the live status.  No need to choose a value by hand.
         The tuner lives in the rc binary (firmware), the cron entry in
         tmpfs (RAM, re-installed at boot) and the settings in nvram -
         nothing is written to /jffs.
  - NEW: GT-BE98 "Remove Wi-Fi regulatory restrictions" toggle
         (Tools > Other Settings) now also unlocks UNII-4 (5G 149-177)
         and 2.4G channels 12/13 for auto channel selection, giving the
         ACS engine the cleanest channels in a congested RF environment.
         Requires a reboot, and is reverted by turning the toggle off.
  - CHANGED: Cleaned up the unrestrict_wl override table - dropped the
             ineffective acs_dfs writes (the flag is re-derived from
             reg_mode on each wireless restart, and DFS is already usable
             via reg_mode=h + the ccode override) and the dead
             wlX_acs_excl_chans clears (rebuilt by set_acs_ifnames()).
  - FIXED: wget build failure with aclocal-1.17 (touch autotools
           stamps before configure).  Backported from gnuton.
  - UPDATED: Merged userspace updates from Asuswrt-Merlin main
             (OpenVPN 2.7.4, dropbear 2026.91, dnsmasq 2.93,
             miniupnpd 2.3.10, CA bundle, networkmap databases).

3006.102.8 (xx-xxx-2026)
  - NOTE: There has been important changes to OpenVPN, some
          necessary with the update to OpenVPN 2.7.  Make
          sure you read the details below, especially if
          running an OpenVPN server with deprecated features
          that have now been removed.

  - NEW: Added tls-crypt V2 authentication support to OpenVPN
         servers.  Don't forget to generate a client key for
         each client that will connect to you.  The keys can
         be generated from the webui, after you have started
         the server with TLS control set to "Encrypt Channel
         V2".  A new button will appear that can generate
         a new client key each time you click on it.
  - UPDATED: OpenVPN to 2.7.4.
  - UPDATED: OpenSSL to 3.0.20 (GT-BE19000AI)
  - CHANGED: VPN Status page can now detect running but
             non-connected WireGuard client tunnels, and
             report them as being in an error state.
  - FIXED: Some webui pages may fail to properly show recent
           changes after clicking on Apply (an outdated
           cached version would be shown instead).  Fixed by
           disabling ETag support for all .asp files.
  - FIXED: Cannot disable wifi 6 mode on Wifi 6 models (upstream
           issue)
  - REMOVED: Support for secret static key authentication
             from both OpenVPN clients and servers.  Deprecated
             since 2.7.0, and considered outdated in terms of
             security.
  - REMOVED: Compression support from OpenVPN server.  Update
             your client configs if you were using it.
             Client support is still available for backward
             compatibility with old remote server setups,
             but expect it to be removed from OpenVPN 2.8.
             If for some reason you absolutely need it for
             your server (despite the security implications),
             you can still enable it through the Custom settings.
  - REMOVED: Some obsolete/non-working OpenVPN settings such
             as fast-io (no longer working with 2.7) or data
             cipher (were replaced with NCP a few years ago).

3006.102.1 (28-Jun-2024)

  This is the initial release of Asuswrt-Merlin based on
  the 3006 codebase.  Only a few specific models are
  currently available, more will be added over time as
  Asus progressively migrates devices to the new codebase.

  3006 introduces a number of major features, these will not
  be listed - please review Asus' own documentation on the
  new features added in 3006 (AKA Asuswrt 5.0).  The two most
  notable ones are VLAN and Guest Network Pro (also called
  Self-Defined Networks, or SDN), both of which are supported
  in Asuswrt-Merlin.

  This initial 3006.102.xx release also includes a number of
  potentially breaking changes over 3004.  The most relevant
  ones will be listed below.

  Note that while Asus uses VPNFusion, Asuswrt-Merlin still
  uses VPNDirector.  The integration with Guest Network Pro
  had to be re-implemented to work with Asuswrt-Merlin,
  which required a few backend changes.

  Due to the VPN backend differences, it's strongly recommended
  to do a factory default reset after coming from the original
  Asus firmware if you used any VPN-related functionality.


  - NEW: Added support for GT-BE98_PRO.
  - NEW: Added support for RT-BE96U.
  - NOTE: Wifi 7 devices don't support NFS (issue with new
          toolchain), QoS classification page (issue with
          TrendMicro BWDPI) or Wifi Radar (not updated by
          Broadcom).
  - NEW: Added dnsmasq-INDEX.conf.add and stubby-INDEX.yml.add,
         which are appended to SDN config files (INDEX = SDN
         index number)
  - NEW: Added dnsmasq-sdn.postconf and stubby-sdn.postconf.
         They take two arguments:
           - path to the config file for that SDN's instance
           - the SDN index number (1 for the first SDN instance)

  - NEW: Rewrote VPN killswitch implementation.  The new method
         uses an always present routing rule to prohibit access to
         the main routing table, so it will be active even if the
         user manually stops a client.  Removing the prohibit rule
         requires disabling the killswitch on the webui.
         The rules are also created before WAN goes up, to reduce
         the risks of leaks between WAN going up and VPN connecting.
  - NEW: Added killswitch support for WireGuard clients.
  - UPDATED: Merged with GPL 3.0.0.6.102_34369.
  - UPDATED: Chart.js was upgraded from 2.x to 3.9, to share the
             same version used by Asus.  Any third party addon
             that used it will need to upgrade their charts to
             the new version.
  - UPDATED: wget to 1.24.5.
  - CHANGED: Switched to a different qrcode generation script, to
             share the same script used by Asus.
  - CHANGED: WireGuard and OpenVPN clients use different iproute2
             table IDs, to be in line with Asus's own table IDs.
             The names defined in rt_tables remain unchanged.
  - CHANGED: Implemented support for Wifi 7 and SDN on the
             Wireless Log page.
  - CHANGED: Implemented DNSDirector webui for SDN.
  - CHANGED: Removed stop/start and "Start with WAN" buttons from
             OpenVPN clients.  There is now just a single
             "Enable" option, which will immediately start the
             client when applying changes, and will also start it
             automatically when WAN comes up.  This is to reduce
             confusion, better integrate into SDN, and match how
             WireGuard clients already worked.
  - CHANGED: ipset is now compiled into the kernel rather than as
             modules (to match with Asus)
  - CHANGED: Removed led_disable nvram, we now share the same AllLED
             nvram as used by Asus for the LED button (and AiMesh sync)
  - FIXED: JS error on Wifi 6e/7 models when toggling DDNS.
  - REMOVED: Option dns_local_cache from Tools -> Tweak settings,
             to avoid issues with SDN that run their own
             dnsmasq instances.
  - REMOVED: Wifi Radar was removed (unsupported by Wifi 7 devices,
             and security issues cited by Asus in their own recent
             releases).
